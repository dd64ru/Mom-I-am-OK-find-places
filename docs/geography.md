# Geographic verification and public Nominatim

The developer deliberately selected public Nominatim for this small, user-triggered private-group venue workflow. Before using it, read the [official public Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/), rechecked on 2026-10-05. It requires an identifiable User-Agent, an application-wide maximum of one request/second, caching and visible OpenStreetMap attribution. It prohibits bulk/systematic POI harvesting, autocomplete, confidential/personal data submissions and generic geocoding services generated by low-code platforms. This application is a bounded personal venue workflow, not a public search API. The owner is responsible for continued compliance; switch providers if usage grows or service access is withdrawn.

`OpenAiSearch` reuses the same OpenAiOAuth, Secret Manager SessionStore and refresh lease as vision. It sends at most three bounded name/category/area clues as JSON data, never images, visibleText, captions or conversation. Static instructions treat clues, city hints and web pages as untrusted. Requests use `store:false`, `stream:true`, `web_search` with low context, a 45-second timeout and bounded streamed output. SIWC forbids `max_output_tokens` and `max_tool_calls`; they are omitted. The client cancels/rejects a stream on a second search item and accepts at most three textual candidates and twenty protocol citations. There is one request, no research retry loop. Hosted search availability depends on selected model and account/workspace policy; its internal work cannot be guaranteed to have a strict billing-token limit.

Only `url_citation` annotations in Responses events/completed output, coupled with a completed web search, become references. Model JSON cannot supply URLs or coordinates. No model-provided URL is fetched. HTTP 400 tool/options rejection returns unavailable textual verification; a single high-confidence vision clue with a city hint may still go to deterministic lookup. Auth/permission failures, malformed output and other failures remain visible and fail closed; Gemini is never a search fallback. This is not a claim that live SIWC web search has been tested.

`PoiProvider` is replaceable. `NominatimPoi` makes at most one `/search` request per resolution, jsonv2, limit three, a project-identifying User-Agent, no redirects, a ten-second timeout and a 100 KB response limit. It uses a seven-day Firestore cache keyed by endpoint and normalized query hash, including negative results. A transactional global gate permits only one in-flight request across instances/revisions, at least 1.5 seconds between completed requests, and at most fifty new requests/day. Busy requests fail for webhook retry instead of launching a parallel burst. A crashed gate owner expires after thirty seconds, beyond the request timeout. Rate state is outside the workspace so workspaces cannot multiply endpoint traffic. These small caps are ceilings, not a target request rate.

Queries contain only public venue/local name, explicit city/area and public address clues. Private conversation, full visible text, image bytes, URLs, credentials and Telegram identities are excluded. Do not enter confidential material into `/area` or a city reply. Provider results must have valid WGS84 coordinates, OSM type/id, a supported venue category, an exact normalized name/alias match and a matching locality/region. Only one match becomes a selectable candidate. Multiple matches, absent city, low confidence, unsupported categories and mismatched names/areas require clarification or remain unresolved. City comparison is deliberately conservative; multilingual locality variants, district-only hints and rural addresses may not match. Names preserve Unicode/local aliases. China coverage depends on actual OSM data; missing coverage is reported without invented coordinates or a paid provider substitution.

Set optional non-secret `NOMINATIM_ENDPOINT` in the GitHub production environment to a compatible HTTPS origin when changing services; no source update is required. Default is the public endpoint. Changing it creates a separate cache key, while the conservative global gate remains. The runtime displays `© OpenStreetMap contributors (ODbL)` on proposals and retains OSM references in canonical Places. Observe [ODbL obligations](https://www.openstreetmap.org/copyright) when later exporting/sharing substantial datasets.

Place IDs hash stable provider identity (OSM type/id), scoped by the workspace collection. Without a stable identity, the fallback hashes normalized name plus coordinates rounded to six decimals; it intentionally avoids fuzzy chain-name merging. Distinct branches with distinct IDs/positions remain distinct. Confirm reads Discovery and Place before writes in one Firestore transaction, creates the Place only if absent, and updates terminal status/link together. Cancel creates no Place. Compare-and-set discovery revisions invalidate old proposals after a city edit and serialize confirmation versus cancellation.
